# Wiki

Living product documentation. Always 1:1 with what the product actually does.

Anyone — human or AI — can update this. The rule is not who writes it; the rule is that it must match reality. When behavior changes, the relevant wiki page changes in the same commit.

## Structure

```
wiki/
├── README.md          # This index
├── ONBOARDING.md      # Team onboarding — generated by /team-onboarding, lives here
├── api/               # API reference — endpoints, schemas, auth, error codes
├── architecture/      # System design, ADRs, data models, component boundaries
├── guides/            # Developer guides, runbooks, how-tos
└── changelog/         # Versioned changelog — what changed, when, and why
```

## What Goes Here

| Content | Location | Notes |
|---------|----------|-------|
| Team onboarding | `wiki/ONBOARDING.md` | Kept current; generated with `/team-onboarding` |
| API endpoint docs | `wiki/api/` | Must match code — update in same commit as behavior change |
| Architecture decisions (ADRs) | `wiki/architecture/` | Immutable once merged |
| System design diagrams | `wiki/architecture/` | Updated when design changes |
| Developer guides / runbooks | `wiki/guides/` | How to do X in this system |
| Changelog entries | `wiki/changelog/` | One file per release or sprint |
| Feature announcements / news | `wiki/changelog/` | Under a `## News` heading |

## Team Onboarding (`wiki/ONBOARDING.md`)

Claude Code's `/team-onboarding` command generates `ONBOARDING.md` and uploads it for sharing. In this harness, that file lives at `wiki/ONBOARDING.md` — not the repo root.

After running `/team-onboarding`, move or configure the output to `wiki/ONBOARDING.md` and commit it. Keep it updated whenever the dev workflow changes significantly.

## Freshness Contract

Wiki entries are bugs when stale. If the product does X but the wiki says Y, fix the wiki in the same PR that changed the behavior. There is no "documentation pass" — docs ship with the feature.

The `finishing-a-development-branch` skill enforces this: Step 0 is a mandatory wiki sync check before any merge or PR is created.

## What Does NOT Go Here

See `.ai/README.md` for ephemeral AI work artifacts (specs, plans, review reports).
